= REM Evidence Configuration

The connector generates ETSI-REM evidence for message lifecycle events.
Generated evidences are electronically signed (XAdES) and include mandatory issuer metadata.

Configuration is provided via `application.properties` under the `connector.evidences.*` prefix.

NOTE: The configuration is validated at startup. A missing or blank mandatory value stops the
connector with an error naming the offending property.

== Signature configuration

Properties under `connector.evidences.signature.*` control how REM evidence XML is signed.

.ETSI-REM Evidences Signature Configuration Properties
[cols="35,40,10,15"]
|===
| Property | Description | Optional | Example

| `connector.evidences.signature.digest-algorithm`
| Digest algorithm used when hashing the business payload referenced by the evidence.
| Yes
| `SHA256`. By default, set to *SHA256*

| `connector.evidences.signature.encryption-algorithm`
| Encryption algorithm of the signing key.
| Yes
| `RSA`. By default, set to *RSA*

| `connector.evidences.signature.keystore.path`
| Classpath or filesystem location of the keystore holding the signing private key.
Use the `file:` or `classpath:` prefix.
| No
| `file:./config/keystores/connector-keystore.jks`

| `connector.evidences.signature.keystore.password`
| Password for the keystore.
| No
| `${EVIDENCES_KEYSTORE_PASSWORD}`

| `connector.evidences.signature.keystore.type`
| Keystore type (for example `JKS` or `PKCS12`).
| Yes
| By default, set to `JKS`

| `connector.evidences.signature.private-key.alias`
| Alias of the private key within the keystore. The corresponding public key must be shared with communication partners.
| No
| `connector_blue`

| `connector.evidences.signature.private-key.password`
| Password to unlock the private key entry.
| No
| `${EVIDENCES_KEY_PASSWORD}`
|===

.Configuration Example
[source,properties]
----
connector.evidences.signature.keystore.path=file:./config/keystores/connector-keystore.jks
connector.evidences.signature.keystore.password=${EVIDENCES_KEYSTORE_PASSWORD}
connector.evidences.signature.keystore.type=JKS
connector.evidences.signature.private-key.alias=connector_blue
connector.evidences.signature.private-key.password=${EVIDENCES_KEY_PASSWORD}
connector.evidences.signature.digest-algorithm=SHA256
----

== Issuer configuration

Properties under `connector.evidences.issuer.*` are embedded into generated REM evidences.
All of them are mandatory and must not be blank.

.Issuer Configuration Properties
[cols="35,40,10,15"]
|===
| Property | Description | Optional | Example

| `connector.evidences.issuer.postal-address.street`
| Issuer street address (mandatory for evidence building).
| No
| `Unknown Street 1`

| `connector.evidences.issuer.postal-address.locality`
| Issuer locality.
| No
| `Unknown`

| `connector.evidences.issuer.postal-address.zip-code`
| Issuer postal code.
| No
| `0000`

| `connector.evidences.issuer.postal-address.country`
| Issuer country.
| No
| `EU`

| `connector.evidences.issuer.as4-party.name`
| AS4 party name of the gateway through which evidences are sent (home party in PMode configuration).
| No
| `Connector Gateway`

| `connector.evidences.issuer.as4-party.endpoint-address`
| AS4 endpoint address of the evidence issuer gateway.
| No
| `mailto:gateway@connector.example`
|===

.Configuration Example
[source,properties]
----
connector.evidences.issuer.as4-party.name=Connector NG
connector.evidences.issuer.as4-party.endpoint-address=mailto:gateway@connector.example

connector.evidences.issuer.postal-address.street=Unknown Street 1
connector.evidences.issuer.postal-address.locality=Unknown
connector.evidences.issuer.postal-address.zip-code=0000
connector.evidences.issuer.postal-address.country=EU
----

== Message processing options

.Evidence Message Processing Configuration
[cols="35,40,10,15"]
|===
| Property | Description | Optional | Default

| `connector.message-processing.send-generated-evidences-to-backend`
| When `true`, generated evidences are also forwarded to the backend after submission to the gateway.
| Yes
| `true`

| `connector.message-processing.auto-trigger-delivery-evidences`
| When `true`, delivery evidences are triggered automatically by the connector.
| Yes
| `false`

| `connector.queues.outbound-evidence-trigger-queue`
| JMS queue for outbound evidence trigger messages received from the backend.
| Yes
| By default, set to `connector.queues.outbound-evidence-trigger-queue`

| `connector.queues.inbound-evidence-trigger-queue`
| JMS queue for inbound evidence trigger messages.
| Yes
| By default, set to `connector.queues.inbound-evidence-trigger-queue`
|===
