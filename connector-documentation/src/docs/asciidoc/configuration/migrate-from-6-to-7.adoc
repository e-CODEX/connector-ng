= Migrate Configuration From 6.x to 7.x

== Overview

Version 7.x reorganises the configuration file. The changes fall into four groups:

* *Renamed prefixes and segments*: for example `connector.ecodex-container` is now
`connector.container`, `c2ctests` is now `connector.c2ctests`, and `key-store` / `trust-store`
are now `keystore` / `truststore`.
* *Removed features*: the `connector.link.gateway` block and the embedded Artemis broker.
* *New property groups*: business domains, message processing, file storage (S3),
security (admin user, JWT, CORS), file deletion, queues and redelivery.
* *Startup validation*: mandatory values are now checked when the connector starts.
A missing or invalid value stops the startup with an error naming the offending property,
instead of failing later at runtime.

WARNING: Old property names that no longer exist in 7.x are *silently ignored*.
Review every renamed prefix in this guide before starting the connector.

== Step-by-step Migration

NOTE: Across all sections, hyphenated store property segments (`key-store`, `trust-store`)
have been normalised to their unhyphenated equivalents (`keystore`, `truststore`) in 7.x.

.Value formats used in 7.x
[cols="25,75"]
|===
| Type | Accepted values

| Duration
| `500ms`, `60s`, `30m`, `6h`, `1d`, ISO-8601 (`PT60S`). A bare number is read as milliseconds.

| Cron expression
| Spring cron with *6 fields* (seconds first), for example `0 0 3 * * *`.

| Resource location
| `classpath:/path/file.xml` or `file:/absolute/path` or `file:./relative/path`.
Always include the prefix.

| URL
| Absolute `http://` or `https://` URL including the host, for example `http://localhost:9000`.
|===

=== Business Domain Configuration

NOTE: Business domain configuration is new in 7.x. In 6.x, the connector operated
with a single implicit domain. You can now define one or more named domains explicitly.

IMPORTANT: If none of the properties below are set, the connector will automatically
create a default domain on startup. Set them explicitly if you need to control
the domain identifier, description, or PMode location.

If you define a domain entry, `identifier`, `description` and all three `pmode` properties
are required for that entry.

.New Business Domain Configuration Properties (7.x)
|===
| Property | Default | Required | Notes

| `connector.business-domains.defaults[0].identifier`
| `default_business_domain`
| Yes (per entry)
| Logical name of the business domain

| `connector.business-domains.defaults[0].description`
| `default business domain`
| Yes (per entry)
| Human-readable description of the domain

| `connector.business-domains.defaults[0].enabled`
| `true`
| No
| Set to `true` to enable this domain at startup

| `connector.business-domains.defaults[0].pmode.file`
| _(none)_
| Yes (per entry)
| Path to the PMode file for this domain. Supports `file:` and `classpath:` prefixes.

| `connector.business-domains.defaults[0].pmode.truststore`
| _(none)_
| Yes (per entry)
| Path to the truststore used with the PMode

| `connector.business-domains.defaults[0].pmode.truststore-password`
| _(none)_
| Yes (per entry)
| Password of the PMode truststore. Inject it at runtime.
|===

.Minimal configuration example (7.x)
[source,properties]
----
connector.business-domains.defaults[0].identifier=default_business_domain
connector.business-domains.defaults[0].description=default business domain
connector.business-domains.defaults[0].enabled=true
connector.business-domains.defaults[0].pmode.file=file:./config/pmode/pmode-blue.xml
connector.business-domains.defaults[0].pmode.truststore=file:./config/keystores/connector-truststore.jks
connector.business-domains.defaults[0].pmode.truststore-password=${PMODE_TRUSTSTORE_PASSWORD}
----

TIP: Additional domains can be configured by incrementing the index:
`connector.business-domains.defaults[1]`, `connector.business-domains.defaults[2]`, etc.

=== Message Processing Configuration

All properties in this section are *new in 7.x*. There are no equivalent properties
in 6.x — these behaviours were either hardcoded or not configurable in previous versions.

.New Message Processing Properties (7.x)
|===
| Property | Default | Required | Notes

| `connector.message-processing.send-generated-evidences-to-backend`
| `true`
| No
| Whether REM evidences (submission acceptance/rejection, delivery/non-delivery)
are forwarded to the backend in addition to the gateway side

| `connector.message-processing.auto-trigger-delivery-evidences`
| `false`
| No
| Whether delivery evidences are triggered automatically

| `connector.message-processing.ebms-id-generator-enabled`
| `true`
| No
| When `true`, the connector generates ebMS message IDs itself rather than
relying on IDs supplied by the backend or gateway

| `connector.message-processing.ebms-id-suffix`
| `connector.ecodex.eu`
| No
| Domain suffix appended to generated ebMS message IDs
(format: `<uuid>@<suffix>`). Only effective when the generator is enabled.

| `connector.message-processing.identifier-suffix`
| `connector.ecodex.eu`
| No
| Domain suffix used when generating conversation IDs and other AS4 identifier fields

| `connector.message-processing.transport-id-suffix`
| `connector.ecodex.eu`
| No
| Domain suffix used for transport-level identifiers,
following the same `<value>@<suffix>` convention

| `connector.message-processing.outbound-verification-mode`
| `STRICT`
| No
| Validation strictness for outbound messages (connector → gateway).
`STRICT` enforces full validation before sending.

| `connector.message-processing.inbound-verification-mode`
| `RELAXED`
| No
| Validation strictness for inbound messages (gateway → connector).
`RELAXED` tolerates non-critical issues on receipt.
|===

NOTE: The three suffix properties (`ebms-id-suffix`, `identifier-suffix`,
`transport-id-suffix`) all follow the same `<value>@<suffix>` convention. They must not be
blank. Set them to a domain you control if you need generated IDs to be traceable to your
deployment.

TIP: If migrating from 6.x where ebMS IDs were supplied externally, set
`ebms-id-generator-enabled=false` to preserve the previous behaviour until
you have confirmed your backend and gateway are compatible with connector-generated IDs.

.Configuration example (7.x)
[source,properties]
----
connector.message-processing.send-generated-evidences-to-backend=true
connector.message-processing.auto-trigger-delivery-evidences=false
connector.message-processing.ebms-id-generator-enabled=true
connector.message-processing.ebms-id-suffix=connector.ecodex.eu
connector.message-processing.identifier-suffix=connector.ecodex.eu
connector.message-processing.transport-id-suffix=connector.ecodex.eu
connector.message-processing.outbound-verification-mode=STRICT
connector.message-processing.inbound-verification-mode=RELAXED
----

=== File Storage Configuration

All properties in this section are *new in 7.x*. In 6.x, the connector used local
filesystem storage only. In 7.x, S3-compatible object storage is the only supported
storage backend. Support for local filesystem storage is planned for a future release.

.New File Storage Properties (7.x)
|===
| Property | Default | Required | Notes

| `connector.file.storage.upload-temp-directory`
| _(none)_
| Yes
| Local directory used for temporary files while uploads are processed.
If you use a placeholder such as `${TEMP_DIR_LOCATION}`, the variable must be defined,
otherwise the startup fails.

| `connector.file.storage.s3.auto-create-bucket`
| `true`
| No
| Create the bucket at startup when it does not exist. Set it to `false` in production
and create the bucket yourself.

| `connector.file.storage.s3.access-key`
| _(none)_
| Yes
| S3 access key ID

| `connector.file.storage.s3.secret-key`
| _(none)_
| Yes
| S3 secret access key

| `connector.file.storage.s3.region`
| _(none)_
| Yes
| AWS region (for example `eu-west-1`). For non-AWS providers this may be an
arbitrary placeholder value required by the S3 client.

| `connector.file.storage.s3.bucket`
| _(none)_
| Yes
| Name of the S3 bucket used to store connector files. Must be a valid S3 bucket name:
3 to 63 characters, lowercase letters, digits, dots and hyphens, starting and ending
with a letter or digit.

| `connector.file.storage.s3.endpoint`
| _(none)_
| No
| S3 endpoint URL. Required for non-AWS providers (MinIO, Silo, OVH Object Storage, etc.)
or when targeting a specific regional/VPC endpoint. When omitted, the standard AWS endpoint
for the region is used. When set, path-style bucket addressing is used.
|===

NOTE: With `auto-create-bucket=true`, the connector creates the bucket at startup when it does
not exist, and the credentials need `s3:ListBucket` and `s3:CreateBucket`. With `false`, the
bucket must exist before startup, otherwise operations that write files fail.

.Configuration example (7.x)
[source,properties]
----
connector.file.storage.upload-temp-directory=${TEMP_DIR_LOCATION}
connector.file.storage.s3.auto-create-bucket=false
connector.file.storage.s3.access-key=${S3_ACCESS_KEY}
connector.file.storage.s3.secret-key=${S3_SECRET_KEY}
connector.file.storage.s3.region=us-east-1
connector.file.storage.s3.bucket=attachments
connector.file.storage.s3.endpoint=http://localhost:9000
----

=== DSS (Digital Signature Service) Configuration

Two property groups have been renamed in 7.x:

* Cache properties: `connector.dss.tl-cache-*` → `connector.dss.cache.*`
* Proxy properties: `connector.dss.http-proxy` / `connector.dss.https-proxy`
→ `connector.dss.proxy.http` / `connector.dss.proxy.https`

The LOTL/TL sources and timestamp server properties are *unchanged*, with one addition:
`policy-oid` is available for timestamp servers.

.DSS Configuration Properties
|===
| Old property (6.x) | New property (7.x) | Notes

| `connector.dss.tl-cache-location`
| `connector.dss.cache.location`
| Renamed — now a dedicated `cache` sub-prefix. Use a resource location (`file:./data/tlcache`).

| `connector.dss.tl-cache-expiration`
| `connector.dss.cache.expiration`
| Renamed — now a dedicated `cache` sub-prefix. Duration, must be positive. Default `1d`.

| _(none)_
| `connector.dss.cache.refresh-cron`
| *New* — Spring cron for refreshing the trusted lists. Default `0 0 */6 * * *`.

| `connector.dss.http-proxy.host`
| `connector.dss.proxy.http.host`
| Renamed — segments reordered (`http-proxy` → `proxy.http`)

| `connector.dss.http-proxy.port`
| `connector.dss.proxy.http.port`
| Renamed — segments reordered

| `connector.dss.https-proxy.host`
| `connector.dss.proxy.https.host`
| Renamed — segments reordered (`https-proxy` → `proxy.https`)

| `connector.dss.https-proxy.port`
| `connector.dss.proxy.https.port`
| Renamed — segments reordered

| `connector.dss.trust-list-sources.*`
| `connector.dss.trust-list-sources.*`
| No change. A blank `lotl-url` or `tl-url` now stops the startup.

| `connector.dss.time-stamp-servers.*`
| `connector.dss.time-stamp-servers.*`
| No change. `url` is required for each server. Optional `policy-oid` is new.
|===

NOTE: Proxy configuration is optional. Only set these properties if your environment
routes outbound DSS traffic (LOTL downloads, CRL and OCSP updates) through a proxy.

.Configuration example (7.x)
[source,properties]
----
# Cache
connector.dss.cache.location=file:./data/tlcache
connector.dss.cache.expiration=1d
connector.dss.cache.refresh-cron=0 0 */6 * * *

# Proxy (optional)
connector.dss.proxy.http.host=proxy1.example.com
connector.dss.proxy.http.port=8080
connector.dss.proxy.https.host=proxy1.example.com
connector.dss.proxy.https.port=8080

# LOTL source (optional)
connector.dss.trust-list-sources.eu.lotl-sources[0].lotl-url=https://ec.europa.eu/tools/lotl/eu-lotl.xml
connector.dss.trust-list-sources.eu.lotl-sources[0].signing-certificates-announcement-uri=https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=uriserv:OJ.C_.2019.276.01.0001.01.ENG
connector.dss.trust-list-sources.eu.lotl-sources[0].pivot-support=true

# Direct TL source (optional)
connector.dss.trust-list-sources.eu.tl-sources[0].tl-url=https://www.signatur.rtr.at/currenttl.xml

# Timestamp servers (optional)
connector.dss.time-stamp-servers.t1.url=http://dss.nowina.lu/pki-factory/tsa/good-tsa
connector.dss.time-stamp-servers.ee-good-tsa.url=http://dss.nowina.lu/pki-factory/tsa/ee-good-tsa
----

== Startup Validation

In 7.x the configuration is validated when the connector starts. If a value is missing or
invalid, the startup stops and the error names the property, for example
`connector.dss.trust-list-sources[eu].tl-sources[0].tl-url: must not be blank`.

The following are checked:

* Mandatory properties must be present and not blank.
* Cron expressions must be valid 6-field Spring cron expressions.
* Durations that represent a threshold or delay must be positive.
* URLs (S3 endpoint, push address) must be absolute `http(s)` URLs.
* Resource files (`ws-policy`, `constraints-xml`) must exist.
* Link configuration names and link partner names must be unique.

NOTE: An empty value (`property=`) counts as *set to blank*, not as unset. Comment the line
out or remove it to use the default.
