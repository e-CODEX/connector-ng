[[docker-install]]
= Containerized Deployment (Docker)

This section uses Docker. The guide is divided into two parts based on your deployment needs and technical expertise.

== Prerequisites

=== Docker Engine and Docker Compose

The Connector runs as a Docker container, so Docker Engine and Docker Compose must be installed on the host machine.
Docker Compose is included with Docker Desktop on Windows and macOS.

To verify your installation:

 docker --version
 docker compose version

Supported versions: Docker Engine **24 or later**, Docker Compose **2.x or later**.

=== Connector image

The Connector is distributed as a Docker image hosted on the e-CODEX repository.
You must have access to the repository and pull the image before running the stack.

=== Database

The Connector uses a relational database to store message state and processing history.
An empty schema and a dedicated database user must be created before the first start — the Connector creates its own tables automatically.

The following DBMS are supported:

* MySQL 8 or higher
* MariaDB 10.6 or higher
* PostgreSQL 14 or higher
* Oracle 19c or higher

=== Message broker — Apache ActiveMQ Classic

The Connector exchanges messages with the Gateway through a JMS message broker.
Apache ActiveMQ Classic **6.x** must be installed, running, and reachable on its TCP port (default: 61616).

=== File storage — S3-compatible

Message attachments are stored in an S3-compatible object store.
A dedicated bucket must be created and credentials provided to the Connector.
Both **MinIO** and **Amazon S3** are supported.

=== e-CODEX Gateway

The Connector acts as a bridge between your backend and an e-CODEX Gateway.
The Gateway must be installed, configured, and network-reachable before the Connector is started.
The Gateway is not part of this distribution — refer to its own installation guide.


== Part 1: Standard Setup

=== Who is this for?

Users who want the connector running with minimum configuration.

=== Steps

==== Step 1 — Pull the Connector image

Pull the Connector image from the e-CODEX repository:

[source,bash]
----
docker pull scm.ecodex.eu/docker/connector:latest
----

To verify the image is available locally:

 docker images | grep connector

==== Step 2 — Configure the environment

[TIP]
====
For more information about these variables, check the link:../configuration/index.adoc[configuration page, window=_self].
====

Create a file named `docker.env` in your working directory.
This file provides the Connector with the connection details for each external service.

.docker.env
[source,properties]
----
# Database
DB_USERNAME=connector
DB_PASSWORD=<your_password>
DB_URL=jdbc:mysql://<db-host>:<db-port>/connector
DB_DRIVER_CLASSNAME=com.mysql.cj.jdbc.MysqlXADataSource
DB_DIALECT=org.hibernate.dialect.MySQLDialect

# File storage (S3 / MinIO)
S3_ACCESS_KEY=<access_key>
S3_SECRET_KEY=<secret_key>
S3_REGION=us-east-1
S3_BUCKET=attachments
S3_ENDPOINT=http://<s3-host>:<s3-port>

# Temporary files
TEMP_DIR_LOCATION=/app/temp

# Message broker (ActiveMQ)
BROKER_URL=tcp://<activemq-host>:61616
BROKER_USER=<broker_user>
BROKER_PASSWORD=<broker_password>
----

==== Step 3 — Set up the certificates

The Connector communicates with both the Gateway and the backend using mutual TLS.
Create a `config/keystores/` folder and place the following files inside:

* `gwlink-keystore.jks` — private key used to sign messages sent to the Gateway
* `gwlink-truststore.jks` — trusted certificates of the Gateway
* `backend-keystore.jks` — private key used to sign messages sent to the backend
* `backend-truststore.jks` — trusted certificates of the backend

Then create `config/application.properties` to reference the keystores and their passwords:

[source,properties][TIP]
====
For a detailed explanation of each variable (defaults, types, and impact), please refer to the `configuration.adoc` file.
====
----
# Gateway link
connector.link.gateway.link-config.properties.endpoint.key-store.path=file:./config/keystores/gwlink-keystore.jks
connector.link.gateway.link-config.properties.endpoint.key-store.password=<your_password>
connector.link.gateway.link-config.properties.endpoint.private-key.alias=<key_alias>
connector.link.gateway.link-config.properties.endpoint.private-key.password=<your_password>
connector.link.gateway.link-config.properties.endpoint.trust-store.path=file:config/keystores/gwlink-truststore.jks
connector.link.gateway.link-config.properties.endpoint.trust-store.password=<your_password>

# Backend link
connector.link.backend[0].link-config.properties.endpoint.key-store.path=file:./config/keystores/backend-keystore.jks
connector.link.backend[0].link-config.properties.endpoint.key-store.password=<your_password>
connector.link.backend[0].link-config.properties.endpoint.private-key.alias=<key_alias>
connector.link.backend[0].link-config.properties.endpoint.private-key.password=<your_password>
connector.link.backend[0].link-config.properties.endpoint.trust-store.path=file:./config/keystores/backend-truststore.jks
connector.link.backend[0].link-config.properties.endpoint.trust-store.password=<your_password>
----

==== Step 4 — Run the Connector

[source,bash]
----
docker run -d \
  --name connector \
  --env-file docker.env \
  -p 30000:30000 \
  -v ./config:/app/config \
  scm.ecodex.eu/docker/connector:latest
----

To watch the logs:

 docker logs -f connector

==== Step 5 — Check it's running

 curl http://localhost:30000/actuator/health

Expected response:

[source,json]
----
{"status":"UP"}
----

Once running, the following endpoints are available:

[cols="2,3", options="header"]
|===
| Endpoint | URL
| REST API | `http://localhost:30000`
| Swagger UI | `http://localhost:30000/swagger-ui/index.html`
|===

== Part 2: Advanced Setup

=== Who is this for?
The target audience of this part are administrators and technical staff familiar with networking, servers, databases and local infrastructure.

=== Scope
* **Focus:** Deployment and configuration.
* **Out of Scope:** Detailed software features and functional usage.

=== Steps

==== Step 1 — Get the project files

 git clone <repository-url>
 cd connector

If you don't use Git, unzip the provided archive and open the `connector` folder.

==== Step 2 — Build the Connector image

 docker build -t connector:latest .

[NOTE]
====
This downloads dependencies and compiles the source code.
It may take a few minutes the first time.
====

==== Step 3 — Create the Docker network

 docker network create ecodex-docker

[NOTE]
====
The network name can be overridden by setting the `ECODEX_DOCKER_NETWORK` environment variable before starting the stack.
====

==== Step 4 — Set your environment variables

Create a file named `docker.env` in the root of the project with the following content:

.docker.env
[source,properties]
----
# Database
DB_USERNAME=connector
DB_PASSWORD=connector                                        # <-- change this
DB_URL=jdbc:mysql://connector-db:3306/connector
DB_DRIVER_CLASSNAME=com.mysql.cj.jdbc.MysqlXADataSource
DB_DIALECT=org.hibernate.dialect.MySQLDialect

# File storage (MinIO)
S3_ACCESS_KEY=admin
S3_SECRET_KEY=admin123                                       # <-- change this
S3_REGION=us-east-1
S3_BUCKET=attachments
S3_ENDPOINT=http://minio-s3:9000

# Temporary files
TEMP_DIR_LOCATION=/app/temp

# Message broker (ActiveMQ)
BROKER_URL=tcp://activemq:61616
BROKER_USER=admin
BROKER_PASSWORD=admin                                        # <-- change this
----

[WARNING]
====
The default values are fine for testing.
**Change all passwords before using this in production.**
====

[NOTE]
====
These variables can also be set directly in `docker/connector/config/application.properties`.
====

==== Step 5 — Set your certificates

The certificates are stored in `docker/connector/config/keystores/`.

Make sure the following files are present:

* `gwlink-keystore.jks`
* `gwlink-truststore.jks`
* `backend-keystore.jks`
* `backend-truststore.jks`

Then open `docker/connector/config/application.properties` and replace the `*****` values with your actual keystore passwords:

[source,properties]
----
# Gateway link
connector.link.gateway.link-config.properties.endpoint.key-store.password=YOUR_PASSWORD
connector.link.gateway.link-config.properties.endpoint.private-key.password=YOUR_PASSWORD
connector.link.gateway.link-config.properties.endpoint.trust-store.password=YOUR_PASSWORD

# Backend link
connector.link.backend[0].link-config.properties.endpoint.key-store.password=YOUR_PASSWORD
connector.link.backend[0].link-config.properties.endpoint.private-key.password=YOUR_PASSWORD
connector.link.backend[0].link-config.properties.endpoint.trust-store.password=YOUR_PASSWORD
----

==== Step 6 — Start the stack

 docker compose up -d

To watch the Connector logs:

 docker compose logs -f connector

==== Step 7 — Check it's running

After a few seconds, run:

 curl http://localhost:30000/actuator/health

You should see:

[source,json]
----
{"status":"UP"}
----

Once the full stack is up, the following services are accessible:

[cols="2,2,3", options="header"]
|===
| Service | URL | Credentials
| Connector REST API | `http://localhost:30000` |
| Connector Swagger UI | `http://localhost:30000/swagger-ui/index.html` |
| Connector database | `http://localhost:30006` |
| MinIO admin console | `http://localhost:9001` | admin / admin123
| ActiveMQ web console | `http://localhost:8161` | admin / admin
| Domibus Gateway | `http://localhost:30010` | admin / 123456
|===

==== Useful commands

[cols="2,3", options="header"]
|===
| Command | What it does
| `docker compose up -d` | Start all services in the background
| `docker compose down` | Stop all services
| `docker compose down -v` | Stop all services and delete all stored data
| `docker compose logs -f connector` | Follow the Connector logs live
| `docker compose ps` | Show the status of all services
| `docker compose restart connector` | Restart only the Connector
|===

[WARNING]
====
`docker compose down -v` permanently deletes the database, messages, and attachments.
Only use it for a full reset.
====
