[[jar-install]]
= Standalone Deployment — JAR Execution

Use this installation option when hosting the connector natively outside any container runtime engine.

NOTE: When upgrading from connector 6.x, first read the configuration migration guide.
Several property names changed, and old names are silently ignored.

== Prerequisites

[cols="1,1,3", options="header"]
|===
| Software | Version | Notes
| Java (JRE) | 21 or later | Only the runtime environment is needed, not the full JDK distribution
| Database | MySQL 8, MariaDB | An empty database schema and a dedicated user role are required
| Apache ActiveMQ Classic | 6.x | Required for message queuing workflows with the e-CODEX Gateway. The broker must be reachable before the connector starts.
| Amazon S3 or MinIO / Silo File storage |  | Required to store message attachments and other connector files. The bucket is created at startup unless `connector.file.storage.s3.auto-create-bucket=false`, in which case it must exist beforehand.
| Local directory for temporary files |  | A dedicated directory owned by the user running the connector, with mode `700`. See step 2.
|===

To check your target server Java version:
[source,bash]
----
java -version
----
The console runtime execution output must yield version `21.x.x` or higher.

== Steps

=== Step 1 — Obtain the Runnable Artifact

* **Option A — Artifact Download:**
** Pull down link:https://scm.ecodex.eu/ui/repos/tree/General/libs-snapshot/eu/ecodex/connector/connector-distribution/{project-version}-SNAPSHOT[a Snapshot distribution version] from the e-CODEX project artifactory.
** Or pull down link:https://scm.ecodex.eu/ui/repos/tree/General/libs-release/eu/ecodex/connector/connector-distribution/{project-version}[a Release distribution version] from the e-CODEX project artifactory.
* **Option B — Compilation From Source:** Run the following command locally:
+
[source,bash]
----
./gradlew build
----
The output executable package will be generated inside `connector-distribution/build/connector-distribution/standalone`.

=== Step 2 — Create the Target Deployment Directory Structure
By default, the following layout configuration is provided in the distribution package:

----
bin/
└── connector-ng.jar
config/
├── application.properties
└── keystores/
    ├── connector-keystore.jks
    ├── connector-truststore.jks
    ├── backend-keystore.jks
    └── backend-truststore.jks
lib/
start.sh
----

Then create the directory for temporary upload files, outside the distribution directory, and
export its location. The connector does not create it. At startup, it checks that the directory
exists, is writable, is not a symbolic link, and is not writable by group or others.

[source,bash]
----
install -d -m 700 -o <connector-user> /path/to/connector/temp
export TEMP_DIR_LOCATION=/path/to/connector/temp
----

WARNING: Do not use a shared, world-writable directory such as `/tmp`. Use a dedicated directory
owned by the user running the connector.

=== Step 3 — Provision Spring Boot Configuration Properties
Populate your configuration template directly inside `./config/application.properties`.

The following values have no usable default and must be set before the first start. Inject secrets
through environment variables or a secrets manager instead of writing them in the file:

[cols="2,3", options="header"]
|===
| Area | Properties

| Database
| The datasource URL, user and password of the empty schema.

| ActiveMQ
| `spring.activemq.broker-url`, `spring.activemq.user`, `spring.activemq.password`

| File storage
| `connector.file.storage.upload-temp-directory`, `connector.file.storage.s3.access-key`, `secret-key`, `region`, `bucket`, and `endpoint` for MinIO/Silo

| Administrator
| `connector.admin.username`, `password`, `email`

| JWT
| `connector.auth.security.jwt.secret`, `issuer`, `refresh-token.expiration`, `refresh-token.cleanup-cron`

| Keystores
| Passwords of the keystores and private keys for evidences, container signature, backend links and truststores

| Evidence issuer
| `connector.evidences.issuer.*`
|===

[TIP]
====
A complete reference of all available enterprise business parameters can be found on the link:../configuration/index.adoc[configuration page,window=_self].
====

.config/application.properties Sample
[source,properties]
----
include::{distributiondir}/src/main/resources/config/application.properties[]
----

NOTE: The configuration is validated at startup. A missing or invalid value stops the connector
with an error naming the offending property (see <<jar-troubleshooting>>).

=== Step 4 — Run the Standalone Native App

Run the connector as a dedicated, non-root user. Before launching the application, ensure `start.sh`
has execute permission:

[source,bash]
----
chmod +x start.sh
----

Then start the application:

[source,bash]
----
./start.sh
----

=== Step 5 — Verify Runtime Status

Once running, the following endpoints are available:

[cols="2,3", options="header"]
|===
| Endpoint | URL
| Root URL | `http://localhost:30000`
| API Health | `http://localhost:30000/actuator/health`
| App Info | `http://localhost:30000/actuator/info`
| Swagger UI | `http://localhost:30000/swagger-ui/index.html`
|===

Sign in to the administration UI with the account configured in `connector.admin.*`.

[[jar-troubleshooting]]
== Troubleshooting startup errors

[cols="2,3", options="header"]
|===
| Symptom | Likely cause

| `Binding to target ... failed`, followed by `Property: ... Reason: must not be blank`
| A mandatory property is missing or empty. Set it, or remove the line to use the default.

| `Could not resolve placeholder 'TEMP_DIR_LOCATION'` (or another variable)
| The environment variable used in `application.properties` is not defined for the user running the connector.

| The startup stops with a message about the temporary directory
| The directory does not exist, is a symbolic link, or is accessible by group or others. Recreate it as in step 2.

| Errors about S3 access denied or an unreachable endpoint
| Wrong credentials or endpoint. If the bucket does not exist, either the credentials need permission to create it, or create it manually and set `auto-create-bucket=false`.

| Connection refused to the broker
| ActiveMQ is not running or `spring.activemq.broker-url` is wrong.
|===
